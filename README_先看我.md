# 宇树Go2机器狗远程二次开发与调试控制台

这是一个独立的新项目，通过社区库 `unitree_webrtc_connect==2.1.2` 控制 Go2 Pro 的低速平移和转向。

如果你希望从 Python 基础开始读懂、运行和修改本项目，请先阅读 [`PYTHON_小白系统学习指南.md`](PYTHON_小白系统学习指南.md)。

## 能做什么

- STA 或 AP 模式连接 Go2；
- AES key 隐藏输入且不保存；
- AES key 自动清理复制内容中的 `Key:` 标签、空格、换行、零宽字符、BOM、包裹引号、`0x` 和 UUID 连字符，并显示整理后的字符数；
- 显式查询并准备 `normal` 或 `mcf` 行走模式，准备完成前后端都会阻止非零速度；
- 点击界面方向按钮后持续前后、横移或转向，直到点击“停止移动”、按空格或窗口失焦；键盘 `W/S/A/D/Q/E` 仍为按住移动、松键停止；
- 控制区按物理键码识别方向键；武装期间仅对控制器窗口临时关闭 IME/切换英文键盘，解除武装时恢复；点击运动按钮会把焦点安全切到按钮本身；
- 确认后可执行安全卧趴、站起、平衡站立、恢复站立、坐下、坐起、打招呼、伸展和比心；每次动作前都会先发送 `StopMove`，动作后必须重新武装才能移动；
- 显示 Go2 前置摄像头的只读实时预览，不录像、不保存；人员识别默认关闭，点击“开启人员识别”后用 YOLOX-Tiny 识别人并画绿色框，点击“关闭人员识别”会立即清除框但不关闭摄像头；
- 摄像头页的“刷新识别”会重新加载人员识别模型并清空旧结果；可在 `F5–F12` 中选择本次运行使用的刷新快捷键。点击按钮或按快捷键时，人员框依次在绿色和红色之间切换；按住快捷键不会连续切换。识别错误只写入“错误日志”页，不会中断摄像头和运动控制；
- 在“自动流程”页编辑、保存和读取按时间执行的流程；支持上述高层动作、等待、六向低速移动和停止，一键确认后自动准备并依次执行；
- 可自行设置速度；默认前后 `0.30 m/s`、横移 `0.20 m/s`、转向 `0.50 rad/s`；
- 本控制器允许范围为前后 `0.05–0.80 m/s`、横移 `0.05–0.50 m/s`、转向 `0.10–1.00 rad/s`；这些是程序设置的安全范围，不是官方标称极限；
- 点击“应用速度”会先停止当前移动再应用，新值只在本次程序运行期间有效；
- 键盘松键停止；键盘事件丢失时，`0.45s` dead-man 自动归零；窗口失焦会停止按钮持续移动并解除武装；
- 后台 `0.35s` 看门狗停止；
- 空格键和红色按钮紧急停止；
- 关闭窗口或主动断开前发送 `StopMove`，失败时重试。

## 明确不做

- 不提供跳跃、舞蹈、翻滚、倒立或高速模式；
- 不在连接后擅自动作；手动移动需要“一键准备并武装”，自动流程需要点击“一键启动流程”并确认完整步骤；
- 自动流程按持续时间控制，不提供精确距离、定位、避障或自主导航；
- 不保存账号密码、AES key 或 access token；
- 不保证电脑断电、进程被强杀或网络硬中断时停止命令一定送达。

## 使用前提

这台 Go2 曾出现右后腿电机绕组过热，用户已确认问题解决。界面仍要求每次确认现场和硬件状态。测试时必须：

1. 在宽阔平整区域清空人员、宠物和障碍物；
2. 实体遥控器始终拿在手中，确认急停方式有效；
3. 首次测试让 Go2 处于稳定低姿态，人员站在运动范围外；
4. 先用实体遥控器让 Go2 站稳，再彻底关闭手机 Unitree Go App；
5. 先运行离线测试，禁止跳过界面的硬件安全确认。

## 第一次使用

需要 Windows 10/11 和 64 位 Python `3.10–3.14`（安装 Python 时建议勾选 `Add Python to PATH`）。安装器会自动寻找兼容版本，并为当前电脑单独创建 `.venv`。

依次双击：

```text
01_安装环境_双击.bat
03_运行离线测试_双击.bat
02_启动安全控制器_双击.bat
```

窗口会按当前电脑的屏幕高度自动调整；在低分辨率或高 DPI 缩放下，可使用窗口右侧滚动条或鼠标滚轮查看下方内容。

安装器还会安装 CPU 版 `ONNX Runtime`、`Pillow`，并从 YOLOX 官方 GitHub Release 下载固定的 `YOLOX-Tiny` ONNX 模型。模型约 20 MB，下载后会核对 SHA-256；模型来源与许可证记录在 `models\README.md`。

按钮输入校验、动作失败和通信错误不会再弹出错误框，而是显示在“错误日志”页。日志同时追加保存到 `%LOCALAPPDATA%\Go2 Controller\logs\error.log`，可点击“打开日志目录”查看。部分固件会在完成 `Heart` 比心后不及时回复 RPC 确认；这种确认超时会写入日志但不会取消后续流程，机器人明确返回非零错误码时仍会安全中止。涉及站起、卧趴、高层动作和自动流程的安全确认框仍会保留，因为它们不是报错，而是执行实体动作前的必要确认。

如果安装器发现 `.venv` 来自其他电脑、项目路径已经变化或环境损坏，会自动删除并重建这个项目专用虚拟环境，不再使用原电脑用户名路径。

## 命令行启动

先完成一次 `01_安装环境_双击.bat`。以后可以不再双击启动文件，打开 PowerShell，进入解压后的项目目录并运行：

```powershell
cd "C:\你的路径\机器狗安全运动控制器"
.\.venv\Scripts\python.exe -m go2_safe_control
```

如果使用传统“命令提示符（cmd）”，运行：

```bat
cd /d "C:\你的路径\机器狗安全运动控制器"
.venv\Scripts\python.exe -m go2_safe_control
```

命令中的项目路径按实际解压位置替换；不要直接调用其他电脑复制来的 `.venv`。原来的 `02_启动安全控制器_双击.bat` 仍可继续使用。

## 给其他电脑使用

不要直接复制整个开发目录，也不要把 `.venv` 发给别人。请在本机双击：

```text
05_生成通用分享包_双击.bat
```

程序会在项目文件夹旁生成 `机器狗安全运动控制器_通用分享版.zip`。分享包自动排除 `.venv`、缓存、日志、旧压缩包、证书、密钥和本地环境文件。对方解压后从 `01_安装环境_双击.bat` 开始，安装器会使用对方电脑自己的 Python 创建环境。

当前已离线验证 Python 3.11 和 Python 3.14 的全新安装及核心模块导入；安装器也允许 64 位 Python 3.10–3.13。若电脑没有兼容 Python，安装器会给出 Python 3.11 官方下载地址，不会继续生成半损坏环境。

当前已验证的 STA 地址是 `192.168.1.124`，界面已将它作为默认值。AES key 由用户粘贴到界面，只保留在当前进程内。

当前固件的设备专属 AES key 必须是 `32` 个十六进制字符（`0-9/a-f`）。它不是 Unitree 账号密码，也不是 Wi-Fi 密码。程序连接成功后会立即清空输入框，因此成功连接后的界面显示空白属于正常安全行为。

如果还没有 AES key，双击：

```text
04_获取AES密钥_双击.bat
```

密码会在独立小窗口中输入，支持 `Ctrl+V` 和“粘贴”按钮；圆点及字符计数可确认粘贴成功，也可临时勾选“显示密码”。密码不会保存。

## 操作顺序

1. 选择 `STA`，检查 IP，粘贴 32 位 AES key；
2. 点击“连接”；
3. 确认 Go2 状态和现场安全；
4. 勾选完整安全确认，只点击一次“一键准备并武装”；程序确认 `normal`/`mcf` 后自动武装，只有未知/旧模式才尝试切换；
5. 等待同时显示“行走模式已就绪”和“已自动武装”；
6. 点击界面的“W 前进”一次即开始持续前进；点击橙色“停止移动（保持武装）”结束，之后可再次选择方向；
7. 键盘仍需按住，松键即停；任何异常立即按空格和实体遥控器急停；
8. 如需趴下，先确保机身和四条腿下方无人、无物，再点击“安全卧趴”并确认；
9. 如需站起，确认机器狗四周和上方无人、无物且地面平整防滑，再点击“一键站起”并确认；卧趴或站起后再次移动均需重新执行一键准备并武装；
10. 平衡站立、恢复站立、坐下、坐起、打招呼、伸展和比心均位于“高层动作”区；执行任何一个动作后，再次移动前都要重新执行“一键准备并武装”；
11. 摄像头可在未武装时单独开启，画面只在内存中显示；
12. 完成后先点击“断开并停止”，再关闭程序。

先确认窗口标题为“宇树Go2机器狗远程二次开发与调试控制台”。首次测试建议保留默认前后 `0.30 m/s`，确认步态正常后再小幅增加。修改三个速度值后点击“应用速度”；程序会先让当前移动归零，再让新速度生效。武装成功后，程序会暂时关闭当前控制窗口的 IME 并切到英文键盘；急停、失焦、断开或退出时恢复原输入环境。IP、AES 和速度输入框允许正常输入，并且在速度框内输入 `W/S/A/D/Q/E` 不会触发移动。点击界面方向按钮会锁存所选方向，不会在鼠标松开时立即发送停止；切换窗口仍会安全停止并解除武装。

## 自动流程

“自动流程”页默认提供以下示例：站起、等待、前进、右转、前进、停止、卧趴。选择表中步骤后，可在“步骤编辑”中更新；也可添加平衡站立、跌倒恢复、坐下、坐起、打招呼、伸展和比心，或删除、上下移动步骤。流程可以保存为 JSON 并再次读取，文件只包含动作、速度和持续时间，不包含 IP、AES key 或账号信息。

移动步骤最长 `10` 秒，等待最长 `30` 秒，单个流程最多 `30` 步且总时长不超过 `120` 秒。移动速度继续受手动控制器相同的三轴安全范围限制。点击“一键启动流程”后，程序会显示完整步骤和预计时长并要求确认；遇到移动步骤时自动准备 `normal/mcf` 行走模式并武装。

流程执行期间，手动方向按钮、方向键和速度修改会被阻止。每一步切换前先归零；流程结束会发送停止并解除武装。点击“立即停止流程”、空格、红色急停、窗口失焦、断线或通信错误都会中止整个流程。自动流程按时间而不是里程执行，地面摩擦、电量和步态会改变实际距离，首次实机只使用短时间低速步骤并由旁人持实体遥控器保护。

## “身体前探但不走”的修正

旧版本连接后直接发送 `Move`，没有先确认 Go2 当前运动模式。参考实现要求先通过
`rt/api/motion_switcher/request` 查询模式。新版固件常用的 `mcf` 与 `normal` 都支持这里使用的基础运动 API，程序会直接接受；只有其他模式才尝试切换为 `normal` 并等待机器人完成站起。
新版由“一键准备并武装”串行完成模式确认和武装，避免两个确认弹窗之间的焦点急停竞态；在识别到 `normal`/`mcf` 前，通信后端仍阻止所有非零速度。

`Move` 是连续控制用的 fire-and-forget 命令，不会返回普通 RPC 响应。程序按 WebRTC MCF 示例使用 `noreply` 消息持续发送速度帧；不能等待回复，否则控制循环会在超时后发送 `StopMove`，表现为机身前探但迈不出持续步态。

旧界面还把鼠标按钮当作 dead-man：按下开始、松开立即停止。一次普通点击通常只维持几十毫秒，因此即使协议正确也只会挪一点。新版将界面方向按钮改为点击开始并持续刷新速度，只有明确点击“停止移动”、空格急停、失焦、断开或通信异常才停止；键盘仍保留按住控制。

这项修正基于协议和参考实现完成了离线验证，但真实步态仍取决于机器人固件、硬件状态和现场条件。
首次实机验证点击“W 前进”后让旁人准备实体遥控器，并在约1米内点击“停止移动”；若仍是身体前探、出现异响、打滑或电机温度异常，立即按空格和实体遥控器急停，不要反复尝试。

## 离线验证

```bat
python -m unittest discover -s tests -v
```

离线测试不会创建 WebRTC 连接，也不会向机器人发送命令。

## 技术依据

- `Move` 使用 Sport API `1008`，参数为 `{x, y, z}`；
- `StopMove` 使用 Sport API `1003`；
- `StandDown` 使用 Sport API `1005`；
- `StandUp` 使用 Sport API `1004`；
- `BalanceStand` 使用 Sport API `1002`，`RecoveryStand` 使用 `1006`；
- `Sit`/`RiseSit` 使用 Sport API `1009/1010`；
- `Hello`/`Stretch`/`Heart` 使用 Sport API `1016/1017/1036`；
- WebRTC 运动请求主题为 `rt/api/sport/request`。
- 运动模式查询/切换使用 `rt/api/motion_switcher/request` 的 `1001/1002`；`normal` 和 `mcf` 均作为可行走模式；
- 摄像头使用 WebRTC video channel，只保留供界面显示的最新一帧；人员识别也只处理最新帧，并在独立线程使用 ONNX Runtime 推理，避免阻塞 Tkinter 和 WebRTC。
- 人员识别采用 YOLOX-Tiny 416×416 ONNX 官方模型，仅保留 COCO `person` 类别；它只负责画框，不会自动触发机器狗动作。

该 WebRTC 库是社区实现，不是宇树官方 SDK。正式部署前仍需结合实机固件和现场安全流程验收。
